# NEAR integration matrix

Checked official sources 12 November 2026. Status distinguishes existing live integration from proposed 2.0 work.

| Component                 | Actual API / auth                                                                                                                | Networks, cost, infrastructure                                                                                | Security and limitations                                                                                              | Tested status / honest fallback                                                                                                                                      |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| NEAR AI Cloud             | OpenAI-compatible `POST https://cloud-api.near.ai/v1/chat/completions`; Bearer API key; structured JSON and streaming documented | Paid inference credits; inference is not a testnet token settlement service                                   | Key remains server-side; inference receipt verification is separate from merely calling the gateway                   | Existing GLM integration live-tested. Reuse behind an inference provider; no invented responses when unavailable.                                                    |
| IronClaw                  | Rust agent OS, onboarding, local encrypted credential store, tool sandbox, persistent memory, routines, web gateway              | Self-hosted runtime with PostgreSQL and operational overhead; not a turnkey NFT-owned multi-tenant agent host | Tool sandbox and endpoint allowlists are useful; confidentiality requires an appropriate deployment and verification  | Evaluated official implementation, not installed or integrated. Use Econia's bounded local runtime behind an explicit provider boundary; do not claim TEE execution. |
| NEAR Agent Market         | Self-hosted REST `/v1/agents/me/assignments`, per-agent `aat_` tokens, messages/start/submit; MCP also supported                 | Marketplace billing documents USD/USDC; no verified valueless testnet environment established                 | External jobs carry paid commitments. Scoped credentials and signed webhook validation required                       | Documentation evaluated, no listing, paid hire, credential or live connector tested. Internal directory/messaging/contracts must operate independently.              |
| NEAR Intents              | Multichain intent/verifier and 1Click API; quote and approval flow                                                               | Not required for native testnet NEAR transfers. Testnet availability for desired service escrow not verified  | Cross-chain trades are outside the hackathon payment scope; no real-value financial integration enabled               | Optional adapter only after separate review. Use native NEAR testnet escrow.                                                                                         |
| NEAR NFTs / authorization | near-api-js, NEP-171, NEP-413, finalized RPC ownership and receipt checks                                                        | Explicit network/account binding; testnet gas and storage use valueless NEAR                                  | No owner privileges based on a stale browser wallet; check current NFT ownership for every sensitive operation        | Existing mainnet NFT/auth tested. New collection and testnet auth must be commissioned separately.                                                                   |
| NEAR native escrow        | Existing native-world Rust custody contract and wallet-prepared calls                                                            | Deploy a separate testnet contract; no mainnet funds or config-toggle production payment switch               | Exact yocto accounting, idempotency, reserves, owner policy and receipt reconciliation before financial state changes | Contract primitives tested; 2.0 subcontract policy and complete acceptance journey remain unimplemented.                                                             |
| Stablecoins               | NEP-141 metadata / balance views; transfer-call settlement requires explicit allowlisted asset adapter                           | No new test stablecoin is assumed. Native test NEAR is initial executable asset                               | Preserve decimals, contract and network; reject arbitrary assets and mainnet contract IDs                             | Existing read tools tested. Testnet token settlement remains deferred until an actual allowlisted contract is verified.                                              |

Sources: [Cloud quickstart](https://docs.near.ai/cloud/quickstart), [Cloud source and API](https://github.com/nearai/cloud-api), [IronClaw](https://github.com/nearai/ironclaw), [self-hosted Market agents](https://docs.market.near.ai/guides/self-hosted-agents), [Market billing](https://docs.market.near.ai/buyers/wallets-and-billing), [Intents](https://docs.near.org/chain-abstraction/intents/overview), [NEAR documentation](https://docs.near.org).
